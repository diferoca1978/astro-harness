# 03 — close-astro-7-upgrade

**Status:** Implemented <!-- Draft | Approved — only a human may change this to Approved -->

## Goal

PR #11 (`fa26496`, merged to `dev` in #11 and to `main` in #12 on
2026-09-25) moved the scaffold to Astro 7 without a spec, and left
`pnpm verify` failing at step 1 because `astro check` does not support
TypeScript 7.0. This spec repairs the gate by pinning TypeScript to `^6`,
and it updates the contract that PR #11 left stale. Every other spec is
blocked until this lands, because `spec-verifier` depends on
`pnpm verify`. Until then, every client cloned from `main` inherits the
broken gate.

What PR #11 changed, verified with `git show fa26496`:

- `astro` ^6.4.7 → ^7.3.5, `typescript` ^6.0.3 → ^7.0.2,
  `@astrojs/netlify` ^7.0.13 → ^8.2.6, `prettier-plugin-astro` ^0.14.1 →
  ^1.1.0, plus minor bumps.
- It removed `baseUrl` from `tsconfig.json` and added
  `minimumReleaseAgeExclude: prettier-plugin-astro@1.1.0` to
  `pnpm-workspace.yaml`.
- It deleted `Cta`, `Summary`, `Services`, `ServiceCard`, `ContactForm`,
  `HeroAbout` and `HeroContact`, and the `nosotros`, `contacto` and
  `politica-privacidad` pages. It renamed `Navbar.astro` to `NavBar.astro`.
- Its commit message ("refactor: reorganize component and page
  structure") mentions none of the version bumps. That history stays as
  it is, and this spec is the written record of the upgrade.

The error today, from `pnpm astro check`:

> `astro check does not currently support TypeScript 7.0. To continue
using astro check, install TypeScript 6 instead.`
> `astro check will be deprecated in a future Astro release.`

## Decisions made and discarded

- **Pin TypeScript `^6` and keep `astro check`.** Background in Engram
  #517 and #518 (search: "astro check TypeScript 6"). In a scratch copy of
  the scaffold, TypeScript 6.0.3 gave 0 errors and 0 warnings in 5.4 s.
  `@astrojs/check` 0.9.10 declares `typescript: ^5.0.0 || ^6.0.0` as a
  peer dependency.
  - _Discarded: removing `astro check` and relying on the build._
    `astro build` does not type-check. In the test, 3 planted errors (a
    data typo, a prop typo and a typo in an unused generator) all passed
    the build. The home page shipped without `<title>` and meta
    description, and `addressLocality` silently disappeared from the
    JSON-LD.
  - _Discarded: `@astrojs/ts-content-mapper`._ It is experimental and
    needs TypeScript 7.1 or later.
  - _Discarded: editing `init.sh` to skip `astro check`._ That hides the
    failure instead of fixing it.
  - _Revisit when:_ Astro ships a stable replacement for `astro check`.
    The `AGENTS.md` bullet records that condition.

- **Remove `minimumReleaseAgeExclude`.** Since pnpm 11,
  `minimumReleaseAge` defaults to 1440 minutes, or 1 day (pnpm 11.0
  release notes, via Context7). This machine runs pnpm 12.4.2, and
  neither the repo nor the user config sets that value.
  `prettier-plugin-astro@1.1.0` was published on 2026-09-24 at 20:34:22
  UTC. PR #11 came about 17 hours later, so the exclude was needed then.
  From 2026-09-25 at 20:34:22 UTC it no longer does anything.
  - _Discarded: keeping it with a comment, or as it is._ Every new clone
    would inherit an exception to supply-chain protection with no
    remaining reason.
  - _Deferred to spec 04 (2026-09-25, during implementation)._ The removal
    can only be verified at or after 2026-09-25T20:34:22Z, about 4 hours
    after the rest of this spec was done and `pnpm verify` passed. Waiting
    would hold up spec 04. The exclude names only
    `prettier-plugin-astro@1.1.0`, does no harm until then and nothing
    after, and spec 04 is implemented after that time anyway. The
    decision to remove it stands.
  - _Discarded: downgrading `prettier-plugin-astro` to 1.0.1 (published
    2026-09-17) so the exclude could go now._ It contradicts **Out**
    (1.1.0 stays), and someone would have to upgrade it again later.

- **Clean up all of the lint damage from PR #11, not only lines 40–41.**
  The plan named 2 dead markers. Checking against the tree showed 6 dead
  markers and one live stub the lint no longer sees. The Footer `<h1>` is
  older than PR #11 (the old stubs had `<h1>Footer</h1>` and
  `<h1>CTA</h1>`). PR #11 only lowercased it, and that hid it from the
  lint.
  - _Discarded: only lines 40–41._ That leaves 4 dead markers and an
    undetected stub.
  - _Discarded: fixing only the lint and leaving the `<h1>`._ The scaffold
    would keep shipping a home page that breaks its own one-`<h1>` rule
    until each client dresses the footer.

- **Add a table row for major-version upgrades and make `pnpm verify`
  mandatory for them.** This deliberately narrows the rule that `verify`
  only runs on request. After a major upgrade, `verify` is the only thing
  that proves the scaffold still type-checks and builds, and PR #11 is
  what happens without it.
  - _Discarded: the row without mandatory `verify`._ It records the step
    but does not enforce the one check that would have caught PR #11.
  - _Discarded: no new row._ The "Add a dependency" row and the spec-first
    gate existed on the day of PR #11 and did not stop it, because a
    version bump does not read as "adding a dependency".

- **A concrete `dist/` check instead of re-running §8.** The §8 test in
  `~/harness-notes/2026-09-24-jsonld-shine-scaffold.md` checked
  dormant-module mechanics (`injectRoute`, conditional collections,
  Actions switched off), and the v2 design replaced them with
  `add-module`. The questions that still matter moved to the specs that
  own them: content collections to spec 09, the Netlify adapter to P4 in
  spec 06.
  - _Discarded: re-running all 8 hypotheses under Astro 7._ It costs time
    and mostly tests code that will never exist.

- **The note on importing `z` from `astro/zod` goes in `AGENTS.md`,
  although `src/` has no zod import today.** Contact forms are
  implemented by hand for each client (no contact module). Whoever writes
  those Actions reads `AGENTS.md`, not spec 09. The Astro upgrade guide
  (v6, via Context7) confirms that `z` from `astro:content` is
  deprecated, and `astro@7.3.5` exports `./zod`.

- **The acceptance criteria are checked on the spec branch, not on
  `main`.** `spec-verifier` runs before the merge. `main` gets the fix
  through the usual `dev` → `main` PR, which is not part of this spec.
